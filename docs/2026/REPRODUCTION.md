# Historical reproduction: what could be run, and what is gone

The brief's §19 asks for one of three labels on every historical result, and
for the label never to be more generous than the facts. This is that
accounting, written before the modern comparison so that no reproduction is
graded by whether it flattered the conclusion.

    ORIGINAL_REPRODUCTION        original code, original environment, original data, original seeds
    PARTIAL_REPRODUCTION         original code, something substituted, and the substitution named
    INDEPENDENT_REIMPLEMENTATION a rewrite. Never called a reproduction.

## 2. Whether the historical code runs at all

It does not, unmodified.

```text
ValueError: setting an array element with a sequence
  src/cg_models.py:333  in CG_LASSO_SOC1_v2
    soc_1_k_sol = np.array([soc_1[x].dual_value ...], dtype=object)
    if soc_1_k_sol.any():
```

`Constraint.dual_value` for a `cp.SOC` is a *list* `[mu, psi]` of ragged arrays
in cvxpy 1.9; `np.array(..., dtype=object)` on it raises under numpy 2, so the
dual is never read and the method cannot take a step.

A second failure follows on any run that reaches a termination path with four
or more iterations:

```text
ValueError: x and y must have same first dimension, but have shapes (1,) and (2,)
  matplotlib, from  plt.plot(iterations[k_init:], upper_bounds[k_init:], ...)
```

`iterations = list(range(1, k))` is `k − 1` points and `master_values` has `k`.
It is a pre-existing defect, not a 2026 one, and it is consistent with the 2025
notes' own transcript, which ends at

```text
Time limit reached
Plotting bounds...
```

and nothing after.

A third, latent: `src/cg_models.py` calls `convex_linnear_regression` on the
`sum_1_comb=True` path and does not define or import it — it lives in
`models.py`. That path would raise `NameError`. It is not on the default path
and was presumably never exercised after the 2025 file split.

### The compatibility copy

`src/cg2026/cg_hist_compat.py` is `src/cg_models.py` with the smallest diff
that makes it execute. `diff src/cg_models.py src/cg2026/cg_hist_compat.py`
is 46 lines, all of it the header, the dual-extraction fix, and the plotting
stub. **No arithmetic changes.** The master, the pricing, the boundedness test,
the tolerances, the stopping criteria, the column construction and every
default argument are the 2025 code.

## 4. What the partial reproduction does confirm

Run on new instances with the compatibility copy, threads pinned to one
(`results/2026/profile.json`):

- **The Lagrangian lower bound is computed only at a large penalty.**
  Corrected: an earlier revision of this file said "never computed", and
  `EXP-0001` then recorded one on four cells -- every one at
  `lambda_ratio = 0.5`, `tol = 1e-8`, one each on
  `sparse-n2000-p500`, `sparse-n2000-p5000`, `sparse-n10000-p1000` and
  `historical-n2000-p500`.

  The boundedness test at `cg_models.py:446` is
  `|psi'X| > 2·sqrt(kappa·tau) − cg_lambda_tol`, and `tau = kappa = lambda_1/2`,
  so its threshold grows with the penalty. At a small penalty it fires on every
  iteration, the Lagrangian model is skipped, and `lagrangian_values` stays
  empty. At a large one it can fail to fire, and a bound is recorded. The 2025
  note *"in the old version we didn't even have a lower bound"* is accurate for
  the regime it was written in and false as a universal.

  Both sides of the boundary are pinned by
  `tests/test_solver_agreement.py::test_the_lagrangian_bound_is_recorded_only_at_large_lambda`
  (0 at `0.15·λmax`, at least 1 at `0.7·λmax`).
- **Termination is the dual-stall heuristic**, not the pricing certificate —
  `HYP-0006`, and the mathematical audit says why it must be: at optimality the
  KKT conditions put `|aᵢ| = λ₁` exactly on the support, and the shipped test is
  `|aᵢ| − λ₁ > −tol`.
- **The master grows and dominates.** On the historical dense-truth family at
  n = 2000, p = 1000, the per-iteration master solve goes from 17 ms to 5.4 s
  over 88 iterations, and the run hits its three-minute limit at a relative
  duality gap of 0.199. The historical material's "deterioration as support and
  master density rise" reproduces.
- **The method lands near the optimum, not on it.** Against LARS on a small
  instance its objective agrees to four digits and its KKT violation is more
  than a hundred times larger.

None of these is a timing claim, and none of them needs MOSEK.
